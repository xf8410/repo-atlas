🔗 兼容性语义

怎么保证新改动不弄坏旧东西。

第一原则：默认关 = 逐位不变

所有补丁默认不生效。不带 token 跑，程序的行为和打补丁前 一个比特都不差。这保证了：主干永远是可信的基准，任何实验都不污染它。

自检方法：bench 里 A 臂（不带 token）和旧基准逐位对比，分数必须完全相等。v10 里 A≡B≡F≡H 四臂等值，就是这个自检。

上游关系

  • 我们的代码上游是 xulai1001/umaai-rs（别人写的原版）。我们是 fork/实验，不往上游推东西
  • 上游更新时走 sync 分支对齐（umaai-rs 有一堆 workbench/sync-* 和 workbench/101x120-upstream-ramen 分支，都是干这个的）
  • 机制知识的上游是实机数据：所有游戏机制必须从游戏包原始文件、内存 dump、master.mdb 实测里来，禁止脑补游戏机制

接口兼容三查

  1. 加字段用默认值：新配置项必须有默认值，且默认值=旧行为（比如 cap_discount_floor 默认 0.0 = 不生效）
  2. 不删不改已有 token 含义：旧 token 的行为冻结，新想法开新 token
  3. 计价诚实：选择层可以看得宽松，但游戏入账层永远按真实规则截断（0008 补丁就是这么做的）

数据文件兼容

规则：master.mdb 等游戏数据表更新时，先比对结构再换；训练数据（状态、策略、价值三元组）的格式改动必须在 uma-data 里留版本记录。三个模块（比赛模拟器/育成模拟器/训练数据）互相独立，禁止跨模块混逻辑。
